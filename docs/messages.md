# Messages

The `api` namespace holds every protobuf message, enum and gRPC service client
generated from the package `sandboxes.api.v1`:

```typescript
import {api} from '@crafting/sandbox-api';

const request = new api.CreateSandboxRequest();
```

To use a specific type in a signature or a field:

```typescript
import {api} from '@crafting/sandbox-api';

class App {
    sandbox?: api.Sandbox;
}
```

The messages are generated by `protoc` with `google-protobuf`, so they are
classes with accessors rather than plain objects. Their names match the protobuf
files exactly; the field accessors use the camel-case form of the field name.
The [protobuf files](../../../../protos/proto/sandboxes/api/v1) are the reference
for what exists and what it means.

## Fields

A scalar field has a getter and a setter, and the setter returns the message, so
the calls can be chained:

```typescript
const meta = new api.ObjectMeta();
meta.setName('my-sandbox').setId(id);

meta.getName(); // "my-sandbox"
```

A message field additionally has `has...()` and `clear...()`, and its getter
returns `undefined` when the field is not set:

```typescript
const sandbox = response.getSandbox();
const name = sandbox?.getMeta()?.getName() ?? '';

if (sandbox?.hasStatus()) {
    // ...
}
```

Unset message fields are why reading nested values needs `?.`: only the fields
which the server actually filled in are present, and which ones those are
depends on the request. The fetch options of a request decide how much detail
comes back.

## Repeated fields

A repeated field is a `List`, with a getter, a setter taking the whole array, and
an `add...` for a single element:

```typescript
const definition = new api.AppDefinition();

const workspace = new api.AppDefinition.Workspace();
workspace.setName('dev');
definition.addWorkspaces(workspace);

definition.getWorkspacesList(); // api.AppDefinition.Workspace[]
```

Note the getter is `getWorkspacesList()`, not `getWorkspaces()`. Mutating the
array a getter returns does modify the message, but `addWorkspaces` is the
intended way to append.

## Map fields

A map field has a single accessor returning a `jspb.Map`:

```typescript
const request = new api.CreateSandboxRequest();
request.getLabelsMap().set('team', 'infra');

request.getLabelsMap().get('team'); // "infra"
for (const [key, value] of request.getLabelsMap().entries()) {
    // ...
}
```

## Enums

An enum is an object of numeric constants, nested under its message when it is
declared there:

```typescript
const stage = sandbox.getStatus()?.getSandbox()?.getRunStage();
if (stage === api.Sandbox.Status.Aggregated.RunStage.READY) {
    // ...
}
```

The zero value is the unspecified one, so an enum field is never absent: it reads
as the unspecified value when the server did not set it.

## Oneof fields

The members of a `oneof` each have their own accessors, and setting one clears
the others. A `get...Case()` method tells which member is set:

```typescript
const composer = new api.Composer();

const fromApp = new api.Composer.FromApp();
fromApp.setAppId(appId);
composer.setFromApp(fromApp);

switch (composer.getMethodCase()) {
    case api.Composer.MethodCase.FROM_APP:
        composer.getFromApp();
        break;
    case api.Composer.MethodCase.FROM_APP_DEFINITION:
        composer.getFromAppDefinition();
        break;
    case api.Composer.MethodCase.METHOD_NOT_SET:
        break;
}
```

## Nested types

A type declared inside a message is reached through the name of that message,
mirroring the protobuf declaration:

| Protobuf | TypeScript |
| --- | --- |
| `Sandbox.Status.Aggregated.RunStage` | `api.Sandbox.Status.Aggregated.RunStage` |
| `Composer.FromAppDefinition` | `api.Composer.FromAppDefinition` |
| `Org.Membership` | `api.Org.Membership` |
| `Subscription.Request` | `api.Subscription.Request` |

## Well-known types

The API uses `google.protobuf.Timestamp` and `google.protobuf.Duration`, which
come from the `google-protobuf` package rather than from this library:

```typescript
import {Timestamp} from 'google-protobuf/google/protobuf/timestamp_pb';

const since = new Timestamp();
since.fromDate(new Date(Date.now() - 3600_000));

const filter = new api.ObjectMetaFilter();
filter.setCreatedSince(since);
```

A `Timestamp` a response carries converts back with `toDate()`.

## Plain objects and the wire format

Every message converts to a plain object, which is convenient for logging and
for tests. The keys are camel-case, repeated fields get a `List` suffix, and maps
become arrays of pairs:

```typescript
console.log(JSON.stringify(sandbox.toObject(), null, 2));
```

`toObject()` is one-way: there is no constructor taking a plain object, which is
why requests are built with setters. Messages also serialize to and from the
protobuf binary format with `serializeBinary()` and the static
`deserializeBinary()`, which is what to use to persist or forward a message
rather than `toObject()`.
